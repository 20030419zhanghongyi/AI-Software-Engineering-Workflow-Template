# FILE_BOUNDARY_RULES.md

> 文件边界规则。约束多 Agent 场景下各 Agent 的文件修改权限。

---

## 核心原则

```text
1. 一个 Agent 不应拥有整个项目的自由修改权。
2. 每个任务必须有明确的 Allowed Files 和 Forbidden Files。
3. 修改 forbidden files 必须暂停。
4. 多个 Agent 不应同时修改同一核心文件。
```

---

## Agent 默认边界

### UI Agent

| 规则 | 说明 |
|------|------|
| 允许修改 | UI 组件、样式文件、布局文件、静态资源引用 |
| 禁止修改 | 状态管理逻辑、数据层代码、业务逻辑、数据库操作 |
| 注意 | 可以调用逻辑层暴露的接口，但不能修改逻辑层实现 |

### Logic Agent

| 规则 | 说明 |
|------|------|
| 允许修改 | 业务逻辑、状态管理、数据流、数据处理函数 |
| 禁止修改 | UI 组件、样式文件、数据库 schema、平台 API 封装 |
| 注意 | 可以调用数据层暴露的接口，但不能修改数据层实现 |

### Test Agent

| 规则 | 说明 |
|------|------|
| 允许修改 | 测试文件、测试配置、mock 数据、测试辅助工具 |
| 禁止修改 | 业务源码、UI 组件、生产配置 |
| 注意 | 发现源码 bug 时应报告，而不是自行修复 |

### Docs Agent

| 规则 | 说明 |
|------|------|
| 允许修改 | README、CHANGELOG、使用文档、注释、docs/ 目录 |
| 禁止修改 | 所有源码、配置文件 |
| 注意 | 可以建议源码修改，但不能直接修改 |

---

## 边界冲突处理

### 多 Agent 修改同一文件

如果多个 Agent 需要修改同一文件：

1. 暂停所有涉及该文件的 Agent。
2. 判断是否可以拆分文件（如将共享类型定义独立为单独文件）。
3. 如果不能拆分，指定一个 Agent 负责该文件，其他 Agent 通过接口调用。
4. 如果必须同时修改，由监督 Agent 协调修改顺序。

### Agent 需要越界修改

如果 Agent 在执行任务时发现需要修改 forbidden file：

1. 立即暂停。
2. 在检查点报告中报告需要越界修改的原因。
3. 等待监督 Agent 判断：
   - 批准越界 → 更新任务卡，允许修改
   - 不批准 → 换一种实现方式
4. 不要自行越界修改。

## 文件归属判断

AI 修改文件时应遵循以下判断流程：

```text
1. 这个文件属于哪个模块？（参考 docs/05_module_boundaries.md）
2. 当前任务分配给哪个 Agent？
3. 这个文件是否在 Allowed Files 中？
4. → 是：可以修改
5. → 否：是否在 Forbidden Files 中？
6. → 是：暂停，报告
7. → 不确定：暂停，询问
```
