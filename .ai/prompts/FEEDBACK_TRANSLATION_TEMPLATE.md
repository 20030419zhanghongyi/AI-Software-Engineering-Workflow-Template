# FEEDBACK_TRANSLATION_TEMPLATE.md

> 用于把用户自然语言反馈转成工程约束。

---

## 用途说明

用户给反馈时通常使用自然语言（如"这个按钮太大了"）。监督 Agent 需要将这些模糊反馈转化为具体的工程约束，下发给子 Agent 执行。这个模板确保反馈被准确转译，不会因为理解偏差导致错误修改。

---

## 反馈转译模板

```markdown
# Feedback Translation

## 用户反馈摘要

[用一句话概括用户的核心反馈]

## 反馈类型

- [ ] 方向调整：用户认为当前方向需要调整
- [ ] 交互修正：用户对 UI/交互不满意
- [ ] 范围缩小：用户认为任务范围太大了
- [ ] 范围扩大：用户希望增加更多功能
- [ ] 紧急停止：用户要求立即停止当前工作
- [ ] 质量问题：用户认为代码或交互质量不达标
- [ ] 优先级调整：用户认为某个部分更紧急
- [ ] 其他：[说明]

## 优先级

- [ ] P0：立即处理，暂停其他工作
- [ ] P1：本轮任务内处理
- [ ] P2：记入后续任务

## 更新后的工程约束

[将用户反馈转化为具体的工程约束]

1. [约束 1，例如：移除主界面的 XXX 按钮]
2. [约束 2，例如：将入口移至设置页面]
3. [约束 3，例如：不修改状态管理逻辑]
4. [约束 4，例如：只允许修改 src/components/xxx/ 下的文件]

## 下发给子 Agent 的修正 Prompt

[生成具体的修正指令，可以直接复制给子 Agent]

```text
@子 Agent 名称：

用户反馈：[原始反馈]

修正要求：
1. [具体修正 1]
2. [具体修正 2]

边界约束：
- 允许修改：[文件列表]
- 禁止修改：[文件列表]
- 验收标准：[具体标准]

请在下一个检查点报告修正结果。
```
```

---

## 使用方式

1. 监督 Agent 收到用户反馈后，按此模板转译。
2. 转译后的工程约束应具体到文件级别。
3. 修正 Prompt 可以直接复制给子 Agent。
4. 所有反馈转译记录应保存到 `.ai-runs/` 对应目录。
