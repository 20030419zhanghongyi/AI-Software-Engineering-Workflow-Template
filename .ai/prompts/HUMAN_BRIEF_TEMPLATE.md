# HUMAN_BRIEF_TEMPLATE.md

> 监督 Agent 面向用户的决策摘要模板。

---

## 用途说明

Human Brief 是监督 Agent 向用户汇报的决策卡片。它不是日志，不是代码 diff，而是面向人的决策摘要。用户通过 Human Brief 快速了解当前状态并做出决策。

---

## Human Brief 模板

```markdown
## Human Brief

### 当前总体状态

[一句话描述当前进展，让用户 3 秒内了解全局]

### 子 Agent 做了什么

| Agent | 完成内容 | 状态 |
|-------|---------|------|
| [Agent 名] | [做了什么] | ✅ 完成 / 🔄 进行中 / ⚠️ 有问题 |

### 我发现的问题

[列出监督 Agent 发现的问题，按严重程度排序]

1. **[问题 1]**：[描述] — 来源：[哪个 Agent]
2. **[问题 2]**：[描述] — 来源：[哪个 Agent]

### 需要用户重点看的地方

[列出需要用户审查的具体内容]

1. [文件/功能/截图]：[为什么需要看]
2. [文件/功能/截图]：[为什么需要看]

### 当前可选决策

[列出用户可以做的选择]

1. **继续**：[选择继续的后果]
2. **小修后继续**：[选择小修的后果]
3. **方向调整**：[选择调整的后果]
4. **暂停 / 回滚**：[选择暂停的后果]

### 我的建议

[监督 Agent 的建议，包含理由]

### 如果用户同意，我将下发的指令

[具体指令，让用户知道"同意"后会发生什么]
```

---

## 使用方式

1. 监督 Agent 在检查点审查中发现需要用户参与的问题时，生成 Human Brief。
2. Human Brief 应简洁、具体、可操作。
3. 不要把子 Agent 的原始日志直接丢给用户。
4. 用户反馈后，监督 Agent 使用 FEEDBACK_TRANSLATION_TEMPLATE 转译反馈。
