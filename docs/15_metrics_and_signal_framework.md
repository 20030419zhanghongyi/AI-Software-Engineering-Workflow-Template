# 15. Metrics and Signal Framework

> 发布后如何判断信号是真实需求还是噪音。

---

## Purpose

定义核心指标和判断框架，防止把噪音当信号。这是 Launch Gate 和发布后复盘的基础。

## When to use

- Launch Gate 定义指标时
- 发布后复盘时
- 判断是否进入 Scale Gate 时

## Inputs

- 发布目标
- 目标用户定义

## Outputs

- 指标定义（写入 LAUNCH_REVIEW_ARTIFACT）

---

## 指标分层

### Level 1：核心指标（必须定义）

只选 1-2 个，直接反映核心假设是否成立。

```text
指标名称
定义（怎么算）
数据来源
阈值（达到多少算验证通过）
```

### Level 2：辅助指标（建议定义）

2-3 个，帮助理解用户行为，但不作为主要判断依据。

### Level 3：虚指标（明确排除）

列出看起来像成果但不是真实信号的数据：

| 虚指标 | 为什么不算 |
|---|---|
| 下载量 / 安装量 | 不代表使用 |
| 页面浏览量 | 不代表价值 |
| 点赞 / 关注 | 不代表付费或留存 |
| 早期用户增长（无留存） | 好奇心驱动，不是需求驱动 |

---

## 信号判断框架

| 信号 | 判断 | 行动 |
|---|---|---|
| 核心指标达标 + 用户留存 | 假设成立 | 进入 Scale Gate |
| 核心指标达标 + 无留存 | 假设部分成立 | 优化留存后再判断 |
| 核心指标未达标 + 有正面反馈 | 需要调整 | 回到 MVP Gate 缩小或调整假设 |
| 核心指标未达标 + 无正面反馈 | 假设不成立 | 回到 Idea Gate |

---

## Human checkpoint

- 指标定义必须由 Human Owner 确认
- 阈值判断必须由 Human Owner 做出
- AI 可以建议指标，不能替人判断

## Rollback option

- 指标定义不清 → 延迟发布，先补定义
- 核心指标未达标 → 回到上一个 Gate 重新评估
- 数据不足以判断 → 延长观察期

---

## 常见失败模式

1. 没有定义指标就发布
2. 不断更换指标以匹配已有数据
3. 只看 Level 3 虚指标
4. 样本量太小就下结论
5. 把 AI 生成的数据当用户反馈
