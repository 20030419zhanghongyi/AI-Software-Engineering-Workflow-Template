# Testing Strategy

> 本文档用于记录项目的测试层级、合并前最低检查、手动测试清单和 CI 要求。

---

## 用途说明

Testing Strategy 文档确保项目有基本的测试保护。AI coding 工具在实现功能时必须同时编写测试，合并前必须通过最低检查。

## 填写指南

- 测试策略要根据项目实际情况制定，不要照搬其他项目的策略。
- 合并前最低检查是硬性要求，越少越好，但必须覆盖核心路径。
- 手动测试清单针对无法自动化的部分（如 UI 交互体验）。
- CI 要求应与合并前最低检查一致。

## 合并前最低检查

> 以下检查必须全部通过，否则不允许合并。

- [ ] 单元测试通过
- [ ] 构建成功
- [ ] 无 lint 错误
- [ ] 无 type check 错误
- [ ] 手动验证核心路径可用

## CI 要求

> CI 应至少执行合并前最低检查中的自动化项目。

- [ ] 运行单元测试
- [ ] 运行构建
- [ ] 运行 lint
- [ ] 运行 type check

## 示例片段

```markdown
## 测试层级

### 单元测试

- **范围**：src/logic/ 下的所有业务逻辑函数
- **工具**：Vitest
- **运行命令**：`npm run test`
- **要求**：新增/修改的业务逻辑必须有对应单元测试

### 集成测试

- **范围**：src/data/ 下的数据库操作
- **工具**：Vitest
- **运行命令**：`npm run test:integration`
- **要求**：数据库 CRUD 和搜索功能必须有集成测试

## 合并前最低检查

- [ ] `npm run test` 通过
- [ ] `npm run build` 成功
- [ ] `npm run lint` 无错误
- [ ] 手动启动应用，搜索功能正常
- [ ] 手动创建、编辑、删除笔记正常

## 测试文件组织

```text
src/
  logic/
    search.ts
    search.test.ts
  data/
    database.ts
    database.test.ts
e2e/
  search.spec.ts
```
```

## 与 AI coding 的关系

AI coding 工具必须：

- 实现功能时同步编写测试，不要最后补测试。
- 合并前确保所有测试通过。
- 测试失败时优先修复测试，不要继续扩展功能。
- 不要跳过或注释掉现有测试。
- 测试代码也要遵守编码规范。
