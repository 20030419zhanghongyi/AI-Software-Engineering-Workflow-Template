# Module Boundaries

> 本文档是约束 AI 不乱改代码的最重要的文档之一。
> 它定义了每个模块的职责、文件归属、依赖方向和禁止跨层调用。

---

## 用途说明

Module Boundaries 文档是 AI coding 的核心安全边界。当 AI 在执行任务时，必须通过本文档判断自己是否有权修改某个文件。没有明确的边界，AI 很容易在修改一个模块时"顺手"改了另一个模块的代码，导致项目结构逐渐混乱。

## 填写指南

- 每个项目都应根据自身情况填写此文档。
- 模块划分不需要很细，但层级必须清晰。
- "不负责什么"比"负责什么"更重要。
- 文件归属要具体到目录级别。
- 允许依赖关系要画清楚方向。
- 禁止跨层调用要特别标注。

---

## 推荐模板

```markdown
# Module Boundaries

## 模块总览

| 模块 | 职责 | 目录 |
|------|------|------|
| UI 层 | 界面渲染和用户交互 | [目录] |
| 逻辑层 | 业务逻辑和状态管理 | [目录] |
| 数据层 | 数据持久化和查询 | [目录] |
| 平台适配层 | 平台相关 API 封装 | [目录] |

---

## UI 层

- **职责**：
  - 渲染界面
  - 响应用户操作，调用逻辑层
  - 展示数据
- **不负责**：
  - 不处理业务逻辑
  - 不直接访问数据库
  - 不直接调用平台 API
- **文件归属**：[列出目录或 glob 模式]
- **允许依赖**：逻辑层
- **禁止依赖**：数据层、平台适配层

---

## 逻辑层

- **职责**：
  - 实现业务规则
  - 管理应用状态
  - 协调数据层操作
- **不负责**：
  - 不渲染 UI
  - 不直接操作 DOM
  - 不关心数据如何存储
- **文件归属**：[列出目录或 glob 模式]
- **允许依赖**：数据层
- **禁止依赖**：UI 层

---

## 数据层

- **职责**：
  - 数据的持久化和读取
  - 索引维护
  - 查询优化
- **不负责**：
  - 不包含业务逻辑
  - 不决定数据何时该读/写
  - 不关心 UI 怎么展示
- **文件归属**：[列出目录或 glob 模式]
- **允许依赖**：平台适配层（如需要）
- **禁止依赖**：逻辑层、UI 层

---

## 平台适配层

- **职责**：
  - 封装平台特定的 API
  - 文件系统操作
  - 系统通知
- **不负责**：
  - 不包含业务逻辑
  - 不直接被 UI 层调用
- **文件归属**：[列出目录或 glob 模式]
- **允许依赖**：无（或标准库）
- **禁止依赖**：逻辑层、UI 层

---

## 层级调用规则

```text
UI 层 → 逻辑层 → 数据层 → 平台适配层

允许：上层调用下层
禁止：下层调用上层
禁止：跨层调用（如 UI 直接调数据层）
禁止：同层循环依赖
```

---

## AI 修改文件时的判断流程

1. 先确定当前任务属于哪个模块。
2. 确认要修改的文件是否属于该模块。
3. 如果文件属于其他模块 → 暂停，报告，请求确认。
4. 如果需要跨模块调用 → 只调用下一层暴露的接口，不要直接操作下层内部。
5. 如果不确定文件属于哪个模块 → 暂停，询问。
```

## 示例片段

```markdown
## 模块总览

| 模块 | 职责 | 目录 |
|------|------|------|
| UI 层 | React 组件、样式 | src/components/, src/styles/ |
| 逻辑层 | 状态管理、业务规则 | src/logic/, src/hooks/ |
| 数据层 | SQLite 操作 | src/data/ |
| 平台层 | Electron IPC、文件系统 | src/platform/ |

## UI 层

- **文件归属**：src/components/**/*.tsx, src/styles/**/*.css
- **允许依赖**：src/logic/, src/hooks/
- **禁止依赖**：src/data/, src/platform/

## 逻辑层

- **文件归属**：src/logic/**/*.ts, src/hooks/**/*.ts
- **允许依赖**：src/data/
- **禁止依赖**：src/components/, src/platform/

## 层级调用规则

UI 层可以调用 Logic 层的函数，但不能 import Data 层。
Logic 层可以调用 Data 层的函数，但不能 import UI 层。
Data 层不能 import 任何上层代码。

## AI 修改判断

如果 AI 要修改 src/data/search.ts，但当前任务是"修改搜索 UI"，
必须暂停——搜索 UI 应该调用 Logic 层的搜索函数，而不是直接修改 Data 层。
```

---

## 与 AI coding 的关系

这是 AI coding 最重要的约束文档。AI coding 工具必须：

- 在修改任何文件之前，判断该文件属于哪个模块。
- 只修改当前任务所属模块的文件。
- 如果需要修改其他模块的文件，暂停并请求确认。
- 严格遵守层级调用规则，不允许跨层调用。
- 在 Checkpoint Report 中报告 Boundary Check 结果。
