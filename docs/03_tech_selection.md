# Tech Selection

> 本文档用于记录最终技术选型及选择理由。

---

## 用途说明

Tech Selection 文档记录项目最终选择了哪些技术、为什么选择、以及放弃了哪些备选方案。它与 Tech Research 文档配合使用：Research 记录调研过程，Selection 记录决策结果。

## 填写指南

- 每个技术选型单独一个条目。
- 选择理由要具体，不要只写"更好"。
- 备选方案和放弃理由也要记录，避免后续重复讨论。
- 选型变更时，更新本文档并同步更新 Decision Log。

---

## 推荐模板

```markdown
# Tech Selection

## TS-001: [选型主题]

- **最终选择**：[选择的技术/方案]
- **选择理由**：
  1. 理由 1
  2. 理由 2
- **备选方案**：
  - [方案 A] — 放弃理由：[为什么不用]
  - [方案 B] — 放弃理由：[为什么不用]
- **已知限制**：[选择方案的已知局限]
- **相关 Decision Log**：[链接到 docs/09_decision_log.md 中的条目]

## TS-002: [选型主题]

- **最终选择**：[选择的技术/方案]
- **选择理由**：
  1. 理由 1
- **备选方案**：
  - [方案 A] — 放弃理由：[为什么不用]
- **已知限制**：[选择方案的已知局限]
- **相关 Decision Log**：[链接]
```

## 示例片段

```markdown
## TS-001: 前端框架

- **最终选择**：React
- **选择理由**：
  1. 生态成熟，社区资源丰富
  2. 我有 React 基础，学习成本最低
  3. AI coding 工具对 React 支持最好
- **备选方案**：
  - Vue 3 — 放弃理由：个人对 Vue 不够熟，且 AI 工具对 React 的生成质量更稳定
  - Svelte — 放弃理由：生态较小，遇到问题时可参考资源少
- **已知限制**：React 项目配置略繁琐，需借助 Vite 简化
- **相关 Decision Log**：ADR-002

## TS-002: 本地存储

- **最终选择**：SQLite（通过 better-sqlite3）
- **选择理由**：
  1. 符合项目本地优先原则
  2. 支持全文搜索（FTS5）
  3. 性能足够个人使用
- **备选方案**：
  - JSON 文件 — 放弃理由：不支持高效查询和全文搜索
  - IndexedDB — 放弃理由：API 复杂，调试困难，且仅限浏览器
- **已知限制**：需要 native binding，Electron 打包时需注意
- **相关 Decision Log**：ADR-003
```

## 与 AI coding 的关系

AI coding 工具应：

- 在实现功能时，使用本文档中记录的技术选型，不要自行替换。
- 如果认为需要更换技术选型，必须先提出建议并讨论，不要直接替换。
- 引入新的技术选型必须更新本文档。
- 不要因为自己更熟悉某个技术就擅自在项目中使用。
