# Tech Research

> 本文档用于记录技术调研过程和结论。

---

## 用途说明

Tech Research 文档用于在技术选型之前，系统记录可选技术方案的调研结果。它帮助个人开发者避免凭直觉选技术，也让后续回顾时能理解当时为什么考虑了某些方案。

## 填写指南

- 每个待选方案单独一个章节。
- 优缺点要实际，不要只写优点。
- 风险要具体，不要写"可能有风险"。
- 调研结论要明确，不要模棱两可。
- 如果调研后决定不做某项技术，也要记录原因。

## 示例片段

```markdown
## 调研主题

本地 Markdown 笔记应用的全文搜索方案

## 调研日期

2024-06-15

---

### 方案 A: SQLite FTS5

- **简介**：使用 SQLite 内置的全文搜索引擎
- **优点**：
  - 不需要额外依赖
  - 搜索性能好
  - 支持中文分词（通过 simple tokenizer 或 jieba 插件）
- **缺点**：
  - 中文分词需要额外配置
  - 需要维护索引表
- **学习成本**：低
- **维护成本**：低
- **风险**：
  - 中文分词质量可能不如专业方案

### 方案 B: Elasticsearch

- **简介**：使用 Elasticsearch 作为搜索服务
- **优点**：
  - 搜索功能强大
  - 中文分词支持好
- **缺点**：
  - 需要运行独立服务
  - 资源占用大
  - 违背"本地优先"原则
- **学习成本**：高
- **维护成本**：高
- **风险**：
  - 违背项目"不依赖网络服务"的约束
  - 个人项目难以维护

---

## 调研结论

选择方案 A（SQLite FTS5）。理由：符合项目本地优先原则，不需要额外服务，维护成本低。
中文分词问题可以通过 jieba 分词插件或自定义 tokenizer 缓解。
```

## 与 AI coding 的关系

AI coding 工具应：

- 在建议引入新技术之前，先在此文档中记录调研过程。
- 不要跳过调研直接选择自己最熟悉的方案。
- 调研结论应体现项目约束，而不是技术热门程度。
- 如果调研后发现不需要引入新技术，也要记录这个结论。
