# Decision Log

> 本文档用于记录重要技术决策（ADR - Architecture Decision Records）。
> 所有重要技术决策都应该能被追溯。

---

## 用途说明

Decision Log 记录每次重要技术决策的背景、选项、理由和后果。它防止"后面自己也忘了为什么这么设计"的问题。无论是人工决策还是 AI 建议，只要是影响项目架构或技术选型的决策，都应记录在此。

## 填写指南

- 每个决策一个条目，按时间倒序排列。
- 背景要写清楚当时为什么需要做这个决策。
- 备选方案至少列出两个。
- 后果要诚实，包括负面后果。
- 后续观察是在决策执行一段时间后回头看的效果。

## 示例片段

```markdown
## ADR-001: 使用 SQLite 作为本地存储

- **日期**：2024-06-15
- **状态**：已采纳

### 背景

项目需要一个本地数据存储方案，支持结构化查询和全文搜索。

### 备选方案

1. JSON 文件：简单但查询效率低，不支持全文搜索
2. SQLite：嵌入式数据库，支持 SQL 和 FTS5
3. IndexedDB：浏览器内置，API 复杂

### 决策

使用 SQLite（通过 better-sqlite3）

### 理由

1. 本地优先，不需要独立服务
2. 支持全文搜索（FTS5）
3. 性能满足个人项目需求
4. 社区成熟

### 后果

- 正面：查询高效、搜索方便
- 负面：需要 native binding，Electron 打包时需额外处理

### 后续观察

使用两个月后，FTS5 中文分词效果一般，后续可能需要引入 jieba 分词。
```

## 与 AI coding 的关系

AI coding 工具必须：

- 架构变更、技术选型变更时，主动建议更新本文档。
- 不要在 Decision Log 为空的情况下做重大架构变更。
- 决策记录应客观，不要只记录正面后果。
- AI 建议的决策也应记录，标注来源。
