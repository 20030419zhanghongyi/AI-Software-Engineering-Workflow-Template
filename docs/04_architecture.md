# Architecture

> 本文档用于记录项目的整体架构、模块关系、数据流和关键约束。

---

## 用途说明

Architecture 文档是项目的技术蓝图。它定义了系统的整体结构和关键约束，是 AI coding 工具在修改代码时必须遵守的最高层级技术文档。

## 填写指南

- 架构图可以用文字描述，不需要 fancy 工具。
- 模块关系要明确方向（谁依赖谁）。
- 关键约束是**不允许破坏的规则**，必须写得非常清楚。
- 当架构发生变化时，必须同步更新本文档。

## 示例片段

```markdown
## 整体架构

```text
┌──────────────────────────┐
│     Electron 主进程       │
│  (窗口管理、文件系统访问) │
├──────────────────────────┤
│     渲染进程 / UI 层      │
│  (React 组件、样式)       │
├──────────────────────────┤
│     业务逻辑层            │
│  (笔记管理、搜索、标签)   │
├──────────────────────────┤
│     数据层                │
│  (SQLite、FTS5 索引)      │
└──────────────────────────┘
```

## 模块关系

| 模块 | 职责 | 依赖 | 被依赖 |
|------|------|------|--------|
| UI | 渲染界面、处理用户交互 | Logic | 无 |
| Logic | 笔记 CRUD、搜索、标签 | Data | UI |
| Data | SQLite 操作、索引维护 | 无 | Logic |

## 数据流

```text
用户点击搜索 → SearchUI 调用 Logic.search()
→ Logic 构造 SQL 查询 → Data 执行查询
→ Data 返回结果 → Logic 过滤排序 → UI 渲染列表
```

## 关键约束

1. UI 层不能直接执行 SQL 查询，必须通过 Logic 层。
2. Logic 层不能直接操作 DOM 或 React 状态。
3. Data 层不能导入 UI 或 Logic 层的代码。
4. Electron 主进程和渲染进程之间的通信只能通过 IPC。
```

## 与 AI coding 的关系

AI coding 工具必须：

- 在修改任何代码前阅读此文档，理解架构约束。
- 严格遵守"关键约束"和"禁止破坏的架构规则"。
- 如果修改可能影响架构，必须先说明影响并请求确认。
- 架构变更必须同步更新本文档和 Decision Log。
- 不要假设项目架构和大厂标准架构一样，以本文档为准。
