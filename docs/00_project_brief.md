# Project Brief

> 本文档用于描述项目的基本信息。项目开始时填写，后续根据项目演进更新。

---

## 用途说明

Project Brief 是项目的入口文档，用于回答"这个项目是什么"这个基本问题。AI coding 工具在开始工作前，应首先阅读此文档以理解项目定位和边界。

## 填写指南

- 项目初期就应填写，不应留空。
- 内容不需要很详细，但要清晰、准确。
- "不做什么"和"做什么"一样重要。
- 当前阶段应诚实标注，不要夸大。

---

## 推荐模板

```markdown
# 项目名称

## 项目是什么

[用 1-3 句话描述项目]

## 目标用户

[谁会用这个项目]

## 核心问题

[项目要解决什么问题]

## 核心功能

- [ ] 功能 1
- [ ] 功能 2
- [ ] 功能 3

## 不做什么

- 不做 XXX
- 不做 XXX

## 当前阶段

[ ] 规划中 / [ ] 原型 / [ ] 开发中 / [ ] 可用 / [ ] 维护中
```

---

## 示例片段

```markdown
# LocalMarkdownNote

## 项目是什么

一个本地 Markdown 笔记管理桌面应用，支持标签、全文搜索和实时预览。
所有数据存储在本地，不需要网络连接。

## 目标用户

个人开发者、写作者、研究人员，需要在本地管理大量 Markdown 笔记的人。

## 核心问题

现有笔记工具要么需要联网，要么不支持纯 Markdown，要么搜索太慢。
我需要一个轻量、本地、快速的 Markdown 笔记管理工具。

## 核心功能

- [x] Markdown 文件夹扫描和索引
- [x] 全文搜索
- [ ] 标签系统
- [ ] 实时预览

## 不做什么

- 不做云同步
- 不做多人协作
- 不做富文本编辑

## 当前阶段

[x] 规划中 / [ ] 原型 / [ ] 开发中 / [ ] 可用 / [ ] 维护中
```

---

## 与 AI coding 的关系

AI coding 工具在接到任务时，必须先读此文档以理解：

- 项目的目标用户和核心问题，避免实现超出范围的功能。
- "不做什么"列表，避免 AI 自行添加不必要的功能。
- 当前阶段，避免在原型阶段就做过度的架构设计。

AI 不应修改此文档中的产品决策，但可以建议更新。
